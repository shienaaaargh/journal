## 🧩 ERD: Why Is This Hard? 😂

Our ERD definitely challenged us this week.

I thought it would just be:

```text
TABLE ─── TABLE ─── TABLE
```

Nope. 😭

We had to think about **facts, dimensions, business keys, surrogate keys, relationships, and especially grain**.

One question keeps coming back:

> 🌾 **What does ONE row represent?**

That simple question changed how I look at tables.

For `student_vle`, repeated rows couldn't simply be removed with `DISTINCT`. Some represented real student activity, so we needed to understand the grain and preserve the clicks through aggregation.

That taught me:

> **Never call something a duplicate until you understand what the row means.**

## 🩺 Wait... I Like Data Quality?

Unexpected plot twist:

**Data Quality might be my favorite part.** 😂

We've been working around six core checks:

| Check                        | Question                           |
| ---------------------------- | ---------------------------------- |
| 🕳️ **NULL**                 | Is required data missing?          |
| 👯 **UNIQUE**                | Are unexpected duplicates present? |
| 📏 **RANGE**                 | Are values reasonable?             |
| 🎯 **ACCEPTED VALUES**       | Are categories valid?              |
| 🔗 **REFERENTIAL INTEGRITY** | Do relationships work?             |
| 📦 **VOLUME**                | Did we receive what we expected?   |

What I really enjoyed was turning those checks into something meaningful:

```text
🟢 PASS → Everything looks good.
🟡 WARN → Investigate, but we can continue.
🔴 FAIL → Critical problem. Stop.
```

Eventually, our tests started feeding toward a bigger idea:

```text
❤️ Overall Health
📊 Checks Passed
🚨 Failed Checks
🛑 Critical Failures
🗂️ Datasets Affected
🕐 Last Checked
```

That's when it clicked for me:

We're not just writing SQL validation queries.

**We're building trust in the pipeline.**

And apparently... I really enjoy making data prove that it's trustworthy. 😂
